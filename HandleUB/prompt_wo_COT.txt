When you insert operations, you MUST satisfy all “Hard Constraints” below.
1. Hard Constraints (MUST Always Hold)
1.1 `tosa.minimum` / `tosa.maximum` operand consistency
-------------------------------------------------------
- Both operands MUST have **identical rank, shape, and element dtype**.
- You MUST NOT rely on implicit broadcasting.
- If shapes differ, you MUST first create a correctly shaped tensor so that the two operands match exactly.

1.2 `tosa.reshape` semantic rule
--------------------------------
- `tosa.reshape` only changes shape; it performs **no data conversion**.
- Output tensor MUST have:
  - the same element type as the input, and
  - the same total number of elements as the input.
- If element count would change, the reshape is illegal and MUST NOT be used.

1.3 Formatting, syntax, and Reference Examples
----------------------------------------------
- Every inserted op MUST be **valid MLIR + TOSA grammar**.
- Attribute layout, type annotations, and line structure MUST **exactly** follow the Reference Examples below.
- You MUST NOT imitate any pattern shown in the Error Examples.
- **You MUST strictly adhere to the operator format in the Reference Examples.**
- All inserted `tosa.minimum` / `tosa.maximum` / `tosa.const` / `tosa.reshape` MUST visually match the style of the corresponding Reference Examples (same ordering of attributes, same placement of types, same quoting style, etc.).
